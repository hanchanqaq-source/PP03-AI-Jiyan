# PP03 V0.2-W1 Portfolio Schema v3 and Page Redesign Plan

> **Execution rule:** implement task-by-task with test-driven development, keep the current `codex/pp03-v0.2-w1-portfolio` worktree, and stop before V0.2-W2.

**Goal:** Add schema v3 dual-mode holdings and rebuild only the portfolio-analysis page so that user snapshots, official-NAV reference values, and intraday estimates remain distinct and auditable.

**Architecture:** `fund_portfolio.py` owns durable v3 user truth and migrations; `app.py` performs mode-aware validation and bounded NAV inference; `fund_data/calculations.py` and `service.py` calculate explicit reference values without mutating snapshots. React consumes the expanded contract through typed dense cards plus page-local add/edit/detail drawers.

**Tech stack:** FastAPI, Pydantic, pytest, React 19, TypeScript, Vite, Tailwind, Vitest, Testing Library.

## Global constraints

- Preserve existing official NAV, history, disclosure, holdings, industry, overlap, cache, stale, and failure-degradation behavior.
- Do not edit other primary pages, navigation, or global routes.
- Never infer a historical cost when cumulative P&L is absent.
- Never overwrite `amount_snapshot`, `cumulative_pnl_snapshot`, or `snapshot_at` during analysis or refresh.
- Current portfolio values and weights prefer shares × latest reliable official NAV; quick mode falls back to the user amount snapshot only when reliable inference/current NAV is unavailable.
- Back up v1/v2 local data before migration and preserve old fields.
- Browser acceptance data lives only under `D:\AI_Workspace\04-Projects\PP03-AI-Jiyan\.tmp\acceptance\v0.2-w1` and is cleaned afterward.
- Deletion remains an accessible page modal; do not use native `confirm`.
