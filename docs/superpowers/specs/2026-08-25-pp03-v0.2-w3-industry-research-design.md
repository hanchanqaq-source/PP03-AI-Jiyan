# PP03 V0.2-W3 行业研究工作台设计规格

**状态：** P0 高保真方案，等待视觉验收
**日期：** 2026-08-25
**继承基线：** `codex/pp03-a2-multi-source-provider-hub@377535e3d8e37976a57be6541f9e0e0d5c114a22`
**范围：** 设计、数据契约、实施边界与隔离预览；不修改生产业务代码
**首个完整布局样板：** 存储；差异化模板：半导体、机器人

## 1. 决策摘要

本 Work 将行业研究定义为一份可连续阅读、可追溯、失败关闭的研究报告，而不是一组互不关联的行情卡片。页面固定保留八段顺序：行业总览、当前周期、产业链、核心数据、资金与估值、核心公司、相关基金、新闻、催化与风险。

采用以下产品决策：

1. **一次只阅读一个激活标签。** 多标签是书签架，不是多行业数据合并器；标签数据、请求、缓存、快照与错误必须以 `industry_id` 隔离。
2. **结论与事实分层。** 每个事实同时携带可用性、核验、时效、来源运行四组状态；页面不得用一个“可信度”徽章覆盖它们。
3. **整份报告锁定同一可信快照。** 新抓取核验中或来源失败时继续显示上一份可信快照，禁止把新旧字段拼成一份看似最新的报告。
4. **AI 只做有界摘要。** AI 只能摘要已准入的事实与证据 ID，不生成数值、关系、排名、周期结论或缺失字段；规则引擎先形成可审计的结论候选。
5. **“完整样板”指信息架构完整，不指数据必须填满。** 没有真实、可授权、已核验的来源时，存储样板仍明确显示“暂无可靠数据”“待核验”或“来源未配置”。
6. **A2-W1 门槛原样继承。** 官方来源可形成“已核验”；两个来源族、内容来源和起源集群均独立且支持同一事实时，才能形成“多源印证”；待核验和冲突内容不进入可信结论。

| 公司订单、基金排名 | 无可信统一合同；且排名/推荐不属于本产品目标 | 不生成、不展示排行榜或买入建议 |

### 4.2 后续实现的来源等级

| 等级 | 定义 | 准入方式 |
|---|---|---|
| A：既有可信能力 | 已在固定头存在并有测试的 A2 新闻/证据、基金披露、来源目录能力 | 仍需对目标字段和日期做端到端验证 |
| B：免费公开候选 | 官方监管披露、公司 IR、可公开访问的价格快照 | 最小真实请求、字段形状、更新时间、许可、频率和失败行为全部验证后接入 |
| C：许可受限 | 会员历史序列、商业行业数据库、企业仪表盘 | 默认禁用；无许可证不发请求，不作为实施前提 |
| D：不可得或未配置 | 没有稳定来源、口径不明或授权未知 | 永久失败关闭，明确空状态 |

公开网页存在不等于可自动采集。TrendForce 的公开价格页可作为“当前快照候选”，历史下载和会员能力必须按许可处理；SIA/WSTS 市场数据属于订阅能力；SEC EDGAR API 可作为无需 Key 的官方公司披露候选。任何候选在真实验证前都不算“当前可得”。

## 5. 行业报告真值契约

### 5.1 四轴状态与兼容映射

不得把以下四类状态合并。API wire schema 一律使用 `snake_case`；Python dataclass 与 JSON 同名，前端 decoder 在边界显式映射为 camelCase，禁止两种命名混发。

```text
availability_status = available | partial | unavailable | unconfigured
verification_status = verified | corroborated | unverified | conflicting | not_evaluated
freshness_status    = fresh | stale | expired | unknown
source_run_status   = healthy | partial_failure | failed | not_configured
```

- `verified`：必须通过 A2 的最终 URL、官方身份、内容支持字段和官方 attestation；“Catalog 标为官方”或“转载官方内容”本身不能升级事实；
- `corroborated`：至少两个来源族、内容来源和起源集群均独立的来源共同支持同一字段；三种独立集合分别保留；
- `unverified`：沿用 A2 存储枚举，界面文案显示“待核验”；不在存储层重命名为 `pending`；
- `conflicting`：存在有效反驳或值冲突，优先于支持状态，不形成综合值；
- `not_evaluated`：来源未配置、不可用或字段不适用，没有候选事实可核验；
- `stale`：仍在允许的上一可信快照窗口内，可展示但必须显式标旧；
- `expired`：超过失效条件，只能留作历史证据，不参与当前结论。

合法组合与显示优先级：

| 条件 | 值来源 | `current_value` | 结论准入 | 页面最高优先提示 |
|---|---|---|---|---|
| 当前官方事实通过 attestation | 当前 run | 有值 | 是 | 已核验 |
| 三重独立来源共同支持 | 当前 run | 有值 | 是 | 多源印证 |
| 候选未核验 | candidate run | 可在候选侧栏有值；trusted report 不含 | 否 | 待核验 |
| 存在冲突 | candidate run | 综合值必须为 `null`，逐来源值只在候选侧栏 | 否 | 冲突 |
| 来源未配置/不可用 | 无 | `null` + `empty_reason` | 否 | 来源未配置/暂无可靠数据 |
| 新 run 失败、旧可信仍在时效内 | `displayed_trusted_snapshot_id` | 旧可信值 | 旧结论可读，不称最新 | 来源失败 + 旧可信快照 |
| 旧可信已过期 | 历史区 | 当前值 `null` | 否 | 已失效 |

## 6. 结论生成与 AI 边界

1. 数据适配器产生带来源和口径的 raw observation；
2. 证据服务按 A2 官方 attestation 和来源独立性判断支持/反驳；
3. 准入器只把 `verified` 或 `corroborated` 观察写入 `DisplayedTrustedReport`；
4. 规则引擎只接收 trusted observations，根据显式阈值产生 `IndustryConclusion`；`cycle_stage/outlook_direction/confidence_level/data_completeness` 是权威结构化结论，缺任一结论所需指标时对应字段为 `null`，`text` 只能是这些结构化字段与证据 ID 的确定性展示摘要，不能承载额外结论；
5. AI 输入只有 `IndustryConclusion[]` 与其允许的 `EvidenceReference[]`，输出合同仅为 `{summary_text, cited_conclusion_ids, cited_evidence_ids}`；
6. 服务端验证所有 ID 都是输入子集，并拒绝新增数字、实体、关系、因果、排名、周期阶段或推荐；验证失败直接回退规则原文；
7. AI 禁止自行检索、读取候选旁路或修改核验状态。

周期阶段、景气方向和可信度都不是自由文本字段。它们必须由规则版本、输入指标、判断依据和失效条件共同组成；规则版本变化触发重新核验。

## 7. 页面信息架构

```text
既有侧栏
└── 行业研究页题头
    ├── 复合粘性区：行业标签 + 添加标签 + 8 个报告锚点
    ├── 隔离演示/数据边界横幅
    ├── 行业状态头：名称、更新时间、来源覆盖、四类计数、刷新状态
    └── 单一连续报告纸面
        ├── 01 行业总览
        ├── 02 当前周期
        ├── 03 产业链
        ├── 04 核心数据
        ├── 05 资金与估值
        ├── 06 核心公司
        ├── 07 相关基金
        └── 08 新闻、催化与风险
```

视觉签名为“证据脊柱”：八段共享一条纵向细线、编号节点和右侧证据边注。区段内部优先使用指标行、比较表、时间线和段落，不把每个字段做成同尺寸卡片。

复合粘性区一次计算高度：标签层在上、锚点层在下；滚动锚点使用 `scroll-margin-top`，避免现有两个 `top-0` 遮挡。

## 8. 八个固定区段

### 8.1 行业总览

显示当前周期阶段、景气方向、数据完整度、可信度、主要依据和失效条件。右侧边注始终可见报告快照、规则版本、最后核验时间和证据入口。缺少足够指标时周期和方向显示“暂无可靠数据”，不得由新闻标题补全。

### 8.2 当前周期

存储样板固定八行：DRAM 价格、NAND 价格、HBM 需求、库存水平、产能利用率、厂商资本开支、服务器需求、消费电子需求。每行显示当前值、变化、日期、四轴状态和证据；不存在可信来源的行仍保留并显示空态。

### 8.3 产业链

存储固定五段：设备与材料、存储设计与制造、封装测试、模组与控制器、服务器/手机/PC/汽车等终端应用。每个节点显示观察范围和证据状态，不用公司名称推断上下游关系。

半导体突出设备材料、设计、晶圆制造、封测、终端；机器人突出核心零部件、整机、软件/视觉、应用，并区分样机、订单、交付和量产。

### 8.4 核心数据

使用紧凑表格展示当前值、环比/同比、历史位置、来源、更新时间、口径和状态。证据展开后显示支持/反驳、独立来源数、原始引用、核验时间和快照 ID。历史样本不足时历史位置必须为空。

### 8.5 资金与估值

板块资金、ETF 份额、估值水平、历史分位与产业指标分离。数据不可用时仍显示四个空态行及原因；禁止用价格涨跌代替资金流，用市盈率单点代替历史分位。

### 8.6 核心公司

只展示有证据的公司、产业链位置、关键指标和与当前行业结论的关系。关系来自官方披露、证券代码和分类证据，不来自名称联想。固定提示“观察对象，不构成推荐”。

### 8.7 相关基金

只允许三层非互换关系：用户显式选中的基金代码、基金官方行业配置、基金披露持仓经证券代码穿透后的行业暴露。官方宽泛配置只能标“官方配置/待穿透”，不得自动等价为当前行业暴露；披露穿透必须使用证券代码和公开分类来源。页面显示数据日期、证据层级和未披露/未知；不读取金额、成本、备注或账号，不生成排行榜、收益承诺或买入建议。没有用户显式输入时显示“还没有基金持仓”。

### 8.8 新闻、催化与风险

复用 A2-W1 可信流水线。7/30/90 天窗口分别显示已核验、多源印证、待核验、冲突；可信结论只消费前两类。催化、风险和反向验证信号并列，冲突和待核验事件不得写入总览结论。

## 9. 标签系统

- 默认标签：半导体、存储、机器人；
- 支持多选、顶部已选、快速激活、移除、拖动和键盘前移/后移；
- 新增自定义标签后立即出现在顶部并激活；ID 使用规范化名称加本地随机后缀，不能覆盖默认标签；
- 现有页面偏好是 `{ids, activeId}`；迁移为两个版本化存储：共享自定义目录 `{id,name,kind}` 与页面选择 `{ids,activeId,order}`。迁移必须保留激活项和顺序；重名复用既有 ID，删除自定义目录项时同步移除页面选择但不删除任何报告证据；
- 数据查询键、缓存键、报告状态和刷新状态全部包含 `industry_id`；
- 自定义标签没有模板时显示“标签已保存，报告模板建设中；系统不会根据标签名称自动补造行业数据”；
- `requested_industry_id` 与 `displayed_industry_id` 分开。用户点击目标标签后先显示目标行业加载/空态；只有目标行业整份报告就绪后才原子更新 active 标签和 `displayed_industry_id`。不得把上一行业内容改挂到目标标签下，也不得闪现另一个行业的字段。

## 10. 状态显示规则

| 场景 | 必须显示 | 禁止行为 |
|---|---|---|
| 已核验 | 值、官方来源、日期、口径、证据 | 省略来源或用“系统数据”替代 |
| 多源印证 | 独立来源数和共同支持字段 | 同一家发布者重复计数 |
| 待核验 | 候选事实和“未进入当前结论” | 写入总览、周期或新闻可信摘要 |
| 冲突 | 分来源并列冲突值、反驳证据 | 平均冲突值或挑一个好看的值 |
| 来源失败且有旧快照 | 来源失败、旧快照 ID/时间、仍显示旧内容 | 把旧内容标成最新 |
| 来源失败且无快照 | “暂无可靠数据” | 显示上次局部缓存或演示值 |
| 部分缺失 | 保留指标行并写明缺失原因 | 为了版面完整而补数 |
| 无持仓 | “还没有基金持仓” | 读取或猜测用户资产 |
| 自定义标签无模板 | “模板建设中” | AI 自动生成模板或行业结论 |

状态必须同时使用文字、图标和边框/纹理；红绿只表达涨跌，状态不依赖颜色。预览中的所有数值、来源、公司和基金紧邻“隔离演示”标记，并永久显示“不代表真实市场、基金或公司数据”。

来源失败或核验中时，顶部隔离演示横幅与报告头必须都显示同一个 `displayed_trusted_snapshot_id`，并标注“当前显示的旧可信快照”。如同时显示新 run/candidate ID，必须单独标注“候选刷新”，不得用同一“快照”标签混放两个角色。

## 11. 视觉与交互

- 继承深蓝黑背景、暖橙主色、现有侧栏、Inter/system 字体、1rem 外层圆角和发丝边框；
- 报告正文主栏约 780px，证据边注约 240px；主内容继续受当前壳层宽度约束；
- 上涨为红、下跌为绿；冲突/失败用红色文字加图标和边框，不与涨跌混淆；
- 标签和锚点保持可见；锚点滚动高亮并写入 URL hash；
- 证据按钮展开来源、核验时间、快照、口径、支持/反驳；无证据时不呈现伪按钮；
- 所有目标至少 44×44px；键盘可操作；焦点可见；弹窗支持 Escape、焦点圈闭和关闭后归还；
- `aria-current="location"` 标识锚点，核验进度使用 `role="status"`，冲突/来源失败使用 `role="alert"`；
- `prefers-reduced-motion` 时取消入场、微光和平滑滚动；
- 768–1279px 把证据边注插回对应段落；小于 768px 时标签和锚点横向滚动，表格转换为保持字段顺序的三行组。

## 12. 隔离高保真预览

预览位于 `.tmp/acceptance/v0.2-w3/p0-preview`，只包含静态 HTML/CSS/JS 和隔离演示对象，不连接生产 API、`VR_DATA_DIR`、浏览器配置或基金数据库。

预览至少可交互验证：

- 存储正常样板；
- 部分数据缺失；
- 待核验和冲突；
- 来源失败但旧可信快照仍可见；
- 无持仓；
- 新增自定义标签后立即置顶且显示模板建设中；
- 半导体、存储、机器人切换不串数据；
- 7/30/90 天新闻窗口和证据展开。

三套行业 fixture 必须分别拥有完整八段、快照 ID、指标、公司、基金与新闻对象；浏览器切换后整份报告只出现当前 `industry_id`。7/30/90 天窗口必须改变可见事件集合、事件数或最早日期，不能只切换按钮样式。

正式截图只提交一张全页存储样板图：`docs/screenshots/v0.2-w3/01-industry-research-storage-preview.png`。临时测试、运行日志和截图辅助文件不进入 Git。

## 13. 验收条件

1. 固定八段顺序和差异化模板可见；连续报告没有退化为同尺寸卡片墙；
2. 每个数据点能显示值或准确空态，并同时显示来源、时间、口径、依据、失效条件、证据和核验/独立性状态；
3. 待核验和冲突内容不进入可信结论；来源失败不删除上一可信快照；
4. 标签创建、激活、切换和隔离可在浏览器验证；
5. 存储、半导体、机器人数据不会互串；无模板标签不会由 AI 补造；
6. 所有预览值显著标注为隔离演示，不可能被误认成真实行情；
7. 没有真实用户数据、API Key、付费来源、生产 Live 或生产业务代码被读取/调用/修改；
8. 高保真预览通过桌面浏览器检查，正式截图可打开且来源路径固定；
9. 后续实现必须按测试先行执行；本 P0 在视觉验收处停止。

## 14. 已解决的普通技术选择

- 使用现有 React/TypeScript/FastAPI/SQLite 栈，不引入新 UI 主题或付费 SDK；
- 报告接口使用原子可信快照，不由浏览器拼接八个独立来源；
- 真值使用四轴状态，不把“演示”“新鲜度”“核验”混为一类；
- 标签偏好继续本地持久化，迁移为版本化记录；
- 公司和基金关系只使用代码与披露证据，不用名称推断；
- 浏览器矩阵使用隔离 fixture；真实来源验证使用最小请求和录制证据，测试默认离线；
- 预览采用无外部依赖的静态页面，避免联网字体、图片和遥测。
