# PP03 V0.2-W2 收口：翻译、来源诊断与缓存治理设计

## 状态与边界

本设计由用户在 2026-08-17 批准，继续停留在 `codex/pp03-v0.2-w2-market-news`，保留当前查询范围修复的未提交实现并完成收口。不得进入 V0.2-W3、行业研究、投研首页、AI 选基、Windows 打包，也不得迁移 `AI_Workspace` 目录。

查询范围仍以《PP03 V0.2-W2 查询范围一致性修复设计》为准。本设计只增加三项彼此有边界的能力：英文资讯中文翻译、失败来源可检查诊断、应用拥有缓存的受控清理。三项能力不得改变事件证据、持仓关联或筛选结果。

## 方案选择

采用“后端受控服务 + 前端按当前查询快照合并”的方案。

- 不使用前端直接调用第三方翻译服务或把 API Key 写入服务器缓存。页面把现有本地 AI 配置随翻译请求发送给本机后端，后端只在当前请求中使用并立即丢弃。
- 不在 RSS 抓取阶段批量翻译全部资讯。只翻译当前页面实际展示的英文事件，单次最多 20 条，避免阻塞抓取并控制模型调用量。
- 不让通用清理器扫描仓库或用户目录。清理器只读取显式登记的项目缓存根目录和文件类型；无法确认归属的文件一律保留。
- 不把 `radar.json` 改造成历史记录库。它继续使用单文件原子替换，翻译缓存和清理状态使用各自独立的原子 JSON 文件。

## 中文翻译

### 数据合同

原始 `title`、`summary` 和原文链接保持既有字段并永久保留，不被翻译覆盖。非中文事件可附加：

- `translated_title_zh`
- `translated_summary_zh`
- `translation_status`：`translated`、`unavailable` 或 `not_required`
- `translation_provider`
- `translated_at`

页面默认优先显示可用中文翻译；每个英文事件提供“查看原文 / 中文”切换。中文不可用时显示原始标题和摘要，并标记“中文翻译暂不可用”。详情抽屉保持相同语言选择，同时始终提供原文链接。

### 请求、缓存与并发边界

新增批量翻译接口，仅接受当前响应中实际需要展示的英文事件，单批最多 20 条。每条输入包含事件 ID、原始标题、已有摘要和原文语言；服务端拒绝空标题、超长输入和超过上限的批次。

缓存键是 `sha256(normalized_title + normalized_summary + source_language)`。缓存值保存中文标题、中文摘要、状态、provider、translated_at 和 `last_accessed_at`。命中时更新最后访问时间，不再次调用模型；90 天未访问后才成为可清理对象。失败结果不长期冒充成功翻译，页面本次降级为原文。

翻译只允许使用项目现有可配置 AI 模型接口。提示词明确要求只翻译原始标题和已有摘要，不增加事实；公司名、产品名、股票代码和专有名词尽量保留原文，必要时用中文后括号保留。后端校验模型返回的结构和长度，不接受额外事件或事实字段。

页面在市场资讯响应成功后异步请求翻译。翻译响应写入前必须同时匹配当前 `queryKey`、`snapshot_id` 和事件 ID；切换筛选后的旧翻译响应不得覆盖新页面。翻译失败不改变事件流、重点、影响统计、详情快照或刷新状态。

## 失败来源详情

### 抓取诊断

每个来源状态扩展为：来源名称、来源 URL、状态、错误类型、脱敏且限长的错误原因、最后一次成功时间、本次是否使用旧缓存、本次返回条数。错误类型只允许稳定枚举：`timeout`、`http_status`、`tls`、`dns`、`connection`、`rss_parse` 和 `unknown`。

抓取器不再吞掉单源异常，但也不把原始异常直接返回页面。脱敏器移除 URL 查询参数中的密钥值、Authorization/Cookie/Token 类内容、用户目录和本地绝对路径，并把原因限制在 200 个字符以内。来源配置中的公开 URL 可以显示，敏感请求头和模型配置永不进入来源状态或日志。

总体来源状态明确区分：

- `all_success`：全部成功且未使用旧缓存；
- `partial_failure`：至少一个来源失败且至少一个来源成功；
- `cached`：当前结果使用仍有效缓存；
- `stale_cache`：全部或部分来源依赖过期缓存；
- `all_failed`：全部来源失败且没有可用当前结果。

### 单源重试与界面

失败数量改为可点击入口，打开详情面板展示上述字段。新增单源重试接口，只允许重试当前 `news_sources.json` 中的精确来源标识，不接受任意 URL。重试成功后把该来源结果与其余来源的当前缓存合并，再以临时文件和原子替换更新 `radar.json`；失败则保留原缓存和诊断状态。

单源重试返回新的完整市场资讯响应或明确的刷新结果。前端只在返回响应的 filters 与当前 query 完全一致时写入，并继续遵守 queryKey、请求序号和 snapshot 绑定。按钮在该来源重试期间禁用，其他来源仍可查看。

## 缓存清理器

### 所有权与保护边界

新增统一缓存注册表，每个类别明确声明根目录、可识别文件、过期时间读取方式和删除资格。清理器只处理：股票盘中行情缓存、基金数据缓存、中文翻译缓存、`.tmp/acceptance` 临时验收目录和应用日志。`radar.json` 保持单文件原子替换，不进行历史累积清理。

以下内容无条件排除：用户真实持仓文件、用户标签与设置、当前有效缓存、Git 跟踪的文档与验收截图、源代码、依赖锁文件，以及不在注册表内的任何文件。当前用户持有基金对应的每个缓存类别中，最新一份有效缓存可标记为 `pinned`；自动清理不得删除 pinned 项。

### 保留期

- 股票盘中行情缓存：过期超过 1 天删除。
- 基金搜索、资料、正式净值和历史净值缓存：过期超过 30 天删除。
- 基金公开持仓、官方行业配置和股票行业分类缓存：过期超过 180 天删除。
- 中文翻译缓存：90 天未访问删除。
- `.tmp/acceptance`：成功验收由收口流程立即删除；异常遗留超过 7 天可自动删除。
- 日志：保留 14 天，并受独立合理总量上限约束。

有效期由缓存元数据读取；元数据缺失、损坏或不能分类时不删除，并在状态接口中计入不可回收项。删除前再次解析绝对路径，要求目标仍位于该类别登记根目录内。

### 500 MB 总上限

应用缓存默认总上限为 500 MB。只有已经满足删除资格的条目可以参与容量回收，顺序固定为：最旧临时文件、最旧过期翻译、最旧过期行情、最旧过期基金缓存。日志按自身保留期与总量上限清理。若剩余空间仍超过 500 MB，但只剩当前有效、pinned 或受保护内容，则停止删除并通过状态接口报告未能回收的超限量。

### 调度、接口和界面

后端启动时检查清理状态；距离上次自动清理不足 24 小时则跳过，否则运行一次。清理状态以原子 JSON 保存上次自动清理时间、扫描量和释放字节。

新增缓存状态接口，返回总缓存大小、各类别大小、文件数、过期数、上次自动清理时间、可回收大小、总量上限和当前是否超限。新增手动清理接口，只执行过期项、临时项和日志策略，不清空用户数据或有效缓存；返回释放空间和清理后的状态。

“数据说明”增加“缓存管理”区域，显示当前占用、分类概览、上次清理时间和“清理过期缓存”按钮。操作期间按钮禁用，完成后显示本次释放空间；失败时显示明确错误但不影响市场资讯页面。

## 测试策略

全部新行为遵循测试先行：先观察失败，再做最小实现，再回归相关套件。

后端覆盖：翻译成功合同、无模型降级、内容哈希复用、批量上限、旧翻译响应边界；异常分类与脱敏、失败来源详情、单源重试白名单和原子合并；缓存分类、各保留期、pinned 保护、用户持仓/设置/跟踪截图保护、500 MB 淘汰顺序、24 小时调度和状态/清理接口。

前端覆盖：有翻译时默认中文并可切换原文、无模型时显示原文、翻译响应受 queryKey 与 snapshot 约束；失败详情和单源重试；数据说明缓存状态与手动清理；当前 query 的成功缓存不会串到其他标签或模式。

最终只在实现完成后运行一次完整后端、前端、旧版兼容和生产构建。浏览器用同一批隔离公开数据完成六组筛选验收、翻译切换、来源失败详情、单源重试、缓存管理和控制台 error/warn 检查。验收成功后删除 `.tmp/acceptance/v0.2-w2`，保留 Git 跟踪的正式截图和文档。
