# PP03 基金投研首版设计

## 目标与边界

在 Vibe-Research `d8c80d4` 基线上增量增加 Windows 本地基金投研样板。首版以“共享标签库 + 页面独立标签偏好”为主线，交付投研首页、市场资讯、行业研究和持仓分析四个主入口；保留原有页面、路由、数据能力与 AI 接口，不做交易、公开部署、多人账户、自动更新或大规模重构。

所有真实数据必须保留来源与更新时间。没有可靠数据时统一返回或展示“暂无可靠数据”；仅用于演示布局的内容必须显示“开发占位数据”或“示例数据”。AI 只总结和解释已提供的数据，不生成净值、价格、持仓、资金或行业指标。

## 基线审计

- 前端为 Vite、React 19、TypeScript、Tailwind，现有路由覆盖每日复盘、资讯雷达、板块中心、个股数据、多空辩论、自选、股票持仓、研报、记录和 AI 设置。
- 后端为 FastAPI 单入口，能力拆分在 `astock.py`、`gstock.py`、`newsradar.py`、`market.py`、`portfolio.py`、`chat.py` 和 `tools.py`，已有 45 个 HTTP 端点。
- 资讯雷达已有 12 赛道、108 个 RSS 源、缓存、合规词过滤和 AI 摘要；现有 UI 没有统一层级标签、页面独立偏好、分类/时间过滤和事件去重模型。
- 本地数据没有 SQLite。股票持仓使用 `~/.vibe-research/portfolio.json`，研报使用用户目录，浏览器偏好、自选和笔记使用安全包装后的 `localStorage`。
- 现有板块页是平铺入口和产业环节短列表，不是连续行业报告；现有持仓是股票仓位，不满足基金字段。

## 采用方案

采用与现有架构一致的轻量增量方案：共享标签库、报告模板、资讯匹配规则和页面偏好放在独立前端 feature 模块；基金持仓新增独立后端 JSON 存储与 API，不改变股票持仓文件；市场资讯继续消费现有 `/api/radar`，行业研究继续消费现有市场、行业和资讯端点。

未采用后端 SQLite 标签中心，因为首版是单机单浏览器、现有项目没有数据库迁移框架，引入 SQLite 会重复现有本地持久化并扩大回归范围。未采用四页替换旧路由，因为任务书要求不删除现有功能；四个 PP03 页面作为主导航，旧页面保留在“原有工具”分组。

## 前端架构

### 路由与导航

- `/research-home`：01 投研首页。
- `/market-news`：02 市场资讯。
- `/industry-research`：03 行业研究。
- `/portfolio-analysis`：04 持仓分析。
- 原有 `/daily-review`、`/intel`、`/sectors`、`/portfolio` 等路由继续可用，放入侧栏“原有工具”。
- 根路由跳转到 `/research-home`。

### 标签系统

`features/tags` 是唯一标签来源，类型包含一级行业、二级行业、细分产业链、投资主题、市场范围和自定义标签。标签记录使用任务书字段：`id/name/slug/type/parent_id/aliases/keywords/description/sort_order/enabled`，并允许 `news_track`、`report_template` 等扩展。

`TagSelector` 提供搜索、按一级行业分组、展开层级、多选、已选数量、取消和确认。`SelectedTagBar` 提供激活、删除、横向滚动和拖动排序。`usePageTags(pageKey)` 把 `market_news` 与 `industry_research` 分别写入 `localStorage`；默认提供半导体、存储、机器人，存储异常时降级为本次会话状态。

### 市场资讯

页面从 `/api/radar` 读取真实 RSS 项，使用标签自身的 `news_track` 与 `keywords` 做确定性匹配。半导体映射 `semi`，机器人映射 `robot`，存储先取 `semi` 再按 DRAM、NAND、HBM、存储器等关键词收窄。

资讯规范化层负责：类别归一、时间窗过滤、标题规范化去重、多来源合并、持仓标签相关性和简单优先级。UI 只消费规范化结果，不内嵌规则。没有可靠情绪分析时统一显示“影响不明确”；AI 摘要是按需操作，失败不影响真实资讯列表。

### 行业研究

报告采用连续纵向文档，顶部粘性标签栏和内部锚点导航。模块顺序固定为总览、周期、产业链、核心数据、资金与估值、核心公司、相关基金、新闻与风险。

存储、半导体、机器人各有不同指标模板。首版允许结构化开发占位数据，但每个字段都有 `data_status`；只有来自现有 API 的值可标记为真实数据并显示来源与更新时间。其他标签可选择，但报告显示“该行业报告模板正在完善”。

### 基金持仓

新页面和新 API 不复用股票持仓语义。基金记录包含代码、名称、持有金额、份额、成本、买入日期、备注和用户确认的关联标签。官方净值、盘中估算、历史净值保持三个独立字段；首版未接可靠基金数据源时不计算虚假值，显示明确空状态。

持仓与行业、资讯的关系仅基于用户确认标签和确定性新闻标签匹配。相关基金模块首版展示数据契约与空状态，不生成排行榜或唯一推荐。

### 投研首页

首页聚合本地基金持仓、两个页面的关注标签和现有 RSS 资讯。信息优先级是“今天发生了什么、为什么与我有关、继续关注什么”。真实数值缺失时显示空状态，不用装饰性图表填充。

## 后端架构

新增 `fund_portfolio.py`，把基金持仓存入 `VR_DATA_DIR`（默认 `~/.vibe-research/fund-portfolio.json`），使用锁和临时文件原子替换。新增 `/api/fund-portfolio` GET、`/api/fund-portfolio/holding` POST/DELETE；校验基金代码、非负金额与份额、日期格式、标签数组。

不修改 `portfolio.py` 的股票模型。`app.py` 只增加基金模型与路由注册。资讯、行情、AI 和行业数据继续使用已有端点，避免重复数据层。

## 错误、空状态与数据真值

- 后端不可达：页面显示连接说明，已选标签和静态报告骨架仍可使用。
- RSS 无缓存或抓取失败：显示刷新入口、失败信息和空列表，不生成新闻。
- AI 未配置或失败：保留真实数据，AI 区显示配置/重试提示。
- 行业指标、基金净值、持仓披露或资金数据缺失：显示“暂无可靠数据”及需要的数据源。
- 仅模板内容：统一徽标“开发占位数据”，不得显示成已确认事实。
- 所有可交互控件提供键盘焦点；标签栏溢出横向滚动；减少动态效果。

## 视觉方向

继承 Vibe-Research 暖橙玻璃主题和现有语义色。行业报告采用“投研长卷”结构：窄分隔线、分段编号、来源脚注和状态徽标形成连续阅读节奏；唯一强调元素是粘性双层导航（页面标签 + 报告锚点），其余模块保持克制，不做等尺寸卡片墙。

## 测试策略

- 纯逻辑：标签搜索/层级、页面独立持久化、排序/删除、资讯匹配/去重/时间窗、报告模板差异和空数据状态。
- 后端：基金持仓 CRUD、验证、原子持久化、损坏文件降级、股票持仓不受影响。
- 组件与构建：标签弹窗、横向标签栏、报告锚点、接口失败与空状态，TypeScript 构建。
- 集成：前后端启动后验证标签添加/删除/切换、刷新、服务重启、多标签、行业切换、新闻过滤和本地基金持仓保存。

## 验收解释

“完整行业报告”指八个规定模块、连续布局、标签切换、来源/更新时间/依据/失效条件和数据真值状态均存在；不意味着首版凭空补齐全部实时行业数据。“相关基金”指模块、契约、持仓关系和明确空状态可用；没有可靠基金数据源时不会伪造候选基金。
