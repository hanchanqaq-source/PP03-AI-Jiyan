# PP03 V0.2-W1 持仓分析第二轮改版设计（Schema v3）

## 规格来源与边界

本设计落实用户确认的“方案 A”：在 V0.2-W1 内扩展持仓模型并重做“持仓分析”页面的信息层级与交互。保留既有真实基金搜索、基金资料、正式净值、历史净值、前十大持仓、行业暴露、组合重合度、行业集中度、缓存与失败降级能力。

本轮只修改持仓分析页面、其内部抽屉/弹窗、持仓 schema、相关 API 和计算。不修改市场资讯、行业研究、投研首页，不新增一级导航或全局路由，不做 AI 选基、Windows 打包、自动更新，也不进入 V0.2-W2。

## 持仓 Schema v3

### 双录入模式

`input_mode` 只有两种值：

- `amount_pnl`：快速模式。`amount_snapshot` 必填，`cumulative_pnl_snapshot` 选填，`snapshot_at` 由服务端记录。
- `shares_cost`：精确模式。`shares`、`avg_unit_cost` 和可选 `buy_date` 保存用户确认的份额与成本信息。

持仓记录保留旧字段，新增字段如下：

| 字段 | 类型 | 语义 |
|---|---|---|
| `schema_version` | `3` | 文件及公开记录的 schema 版本 |
| `input_mode` | `amount_pnl \| shares_cost` | 当前录入模式 |
| `amount_snapshot` | `number \| null` | 用户录入时点的持有金额快照 |
| `cumulative_pnl_snapshot` | `number \| null` | 用户录入时点的累计盈亏快照 |
| `snapshot_at` | `ISO datetime \| null` | 金额快照时间 |
| `shares` | `number \| null` | 用户份额或明确标记的推算份额 |
| `avg_unit_cost` | `number \| null` | 用户确认的平均单位成本 |
| `buy_date` | `YYYY-MM-DD \| null` | 用户输入的买入日期 |
| `shares_source` | `user \| inferred \| null` | 份额来源 |
| `basis_nav` | `number \| null` | 推算份额所用的正式净值 |
| `basis_nav_date` | `YYYY-MM-DD \| null` | 推算依据净值日期 |
| `shares_inference_note` | `string \| null` | 明确说明推算口径、非用户确认份额 |
| `notes` | `string` | 用户备注 |
| `custom_tag_ids` | `string[]` | 用户选择或新增的标签 |

兼容字段 `avg_cost`、`legacy_name`、`legacy_amount`、`legacy_cost`、`manual_name`、`cost_confirmation_required` 不删除。只有语义明确的精确模式写入才同步 `avg_cost` 与 `avg_unit_cost`；不得把旧 `cost` 擅自解释成单位成本。

### 验证规则

- `amount_pnl` 要求有限数且大于零的 `amount_snapshot`；累计盈亏可为空、为零或为负，但必须是有限数。
- `shares_cost` 要求有限数且大于零的 `shares`；`avg_unit_cost` 可为空，填写时必须为有限数且不小于零；买入日期必须合法。
- NaN、正负无穷、负金额、负份额和负成本均拒绝。
- 快速模式不以获得可靠净值为保存前置条件。
- 用户修改快速模式的金额或累计盈亏时生成新的 `snapshot_at`；普通数据刷新和系统计算不得修改快照字段。
- 用户补充真实份额后切换为 `shares_cost`，`shares_source=user`；既有快照字段继续保留，不被清空或覆盖。

### 正式净值推算份额

保存快速持仓时，如果存在大于零、未过期且数据状态可靠的正式净值，则计算：

`inferred_shares = amount_snapshot / basis_nav`

同时保存 `shares_source=inferred`、`basis_nav`、`basis_nav_date` 和推算说明。推算份额不伪装为用户确认份额。若正式净值不可用或不满足可靠性门槛，仍保存金额快照，并返回“用户录入金额 / 暂无可核验份额”。

### 迁移与备份

首次读取 v1 或 v2 文件时，先在原数据目录创建包含原 schema 版本和时间戳的备份，备份内容与原文件字节完全一致，再原子写入 v3：

- v2 记录统一标记 `input_mode=shares_cost`；有效既有份额标记 `shares_source=user`；明确的 `avg_cost` 复制到 `avg_unit_cost`。
- v1 记录统一标记 `input_mode=shares_cost`；保留代码、份额、日期、备注和标签；旧 `cost` 只保存在 `legacy_cost`，继续要求用户确认。
- 两类迁移记录的快照字段均为空；旧字段、备注、标签、份额、成本和日期均不删除。

## 计算与 API 真值合同

### 三类金额必须分开

API 和页面同时区分：

1. 用户快照：`amount_snapshot`、`cumulative_pnl_snapshot`、`snapshot_at`。
2. 正式净值参考值：份额乘最新可靠正式净值。
3. 盘中估算参考值：以当前正式参考值或可靠回退值结合盘中估算涨跌率计算。

系统计算结果永远不得反写用户快照。

### 当前组合总值和权重

快速模式的总值和权重按以下优先级计算：

1. 存在可靠 `inferred_shares` 且存在最新可靠正式净值时，使用 `inferred_shares × latest_official_nav`。
2. 无法可靠推算或最新正式净值不可用时，回退 `amount_snapshot`。
3. 两者均不可用时为 `unavailable`，不猜测。

精确模式使用用户份额乘最新可靠正式净值。组合重合度、行业集中度、持仓占比和组合总值统一使用该“当前参考市值”，不得永久固定使用 `amount_snapshot`。

API 为每只持仓返回：

- `user_amount_snapshot`、`user_cumulative_pnl_snapshot`、`snapshot_at`
- `official_market_value`、`intraday_market_value`
- `position_value`、`position_value_basis`
- `reference_total_cost`、`profit_loss`、`return_rate`
- `today_estimated_profit_loss`、`intraday_change_pct`
- 份额来源、依据净值、数据状态和缺失字段

为兼容既有消费者可暂时保留 `total_cost` 和 `market_value` 别名，但页面使用显式字段。

### 盈亏规则

快速模式：

- `reference_total_cost = amount_snapshot - cumulative_pnl_snapshot`
- 只有参考总成本大于零时，`return_rate = cumulative_pnl_snapshot / reference_total_cost × 100`
- 未填写累计盈亏时，累计盈亏与收益率均为 `null`，页面显示“待补充”，不猜测历史成本。

精确模式沿用份额与平均单位成本计算；成本缺失或语义未确认时不计算累计盈亏和收益率。

今日估算继续使用既有可信度门槛。通过门槛时，快速模式以当前参考市值为基数计算今日估算金额和盘中参考市值；未通过时显示“暂无可靠数据”。

### 组合汇总完整性

组合摘要返回最新正式净值日期、可盘中估算数量、仅正式净值数量及累计盈亏完整性。部分持仓缺少累计盈亏时，页面不得把部分合计伪装成完整合计，必须显示“待补充”或明确部分口径。

## 页面结构与交互

### 空持仓

无持仓时只显示一个紧凑空状态：“还没有基金持仓”“先搜索公开基金，再填写当前持有金额，建立你的本地持仓看板”和“添加第一只基金”按钮。组合总览、基金列表、组合重合度和行业集中度不展开。

### 标题、总览与数据状态

标题为“我的持仓”，副信息只显示基金数量；右侧依次提供刷新、“数据说明”和橙色主按钮“添加基金”。

有持仓时只显示四张紧凑蓝黑渐变总览卡：总持有金额、今日估算盈亏、累计持有盈亏、累计收益率。总览卡之后单独显示数据状态栏，承载最新官方净值日期、可盘中估算数量和仅正式净值数量，不把这些信息做成额外大卡。

所有金额和收益颜色遵循 A 股习惯：红涨、绿跌；不可用数据使用中性灰或“待补充”，不得用涨跌色暗示不存在的数值。

### 当前基金持仓

核心区域采用高密度桌面表格/列表，顶部先放筛选与排序工具栏：

- 筛选：全部、上涨、下跌、盈利、亏损、待补充。
- 排序：持有金额、今日涨跌、今日盈亏、累计盈亏、累计收益率、基金名称。

桌面列固定为“基金名称 / 代码”“持有金额 + 占比”“今日估算”“累计盈亏”“官方净值 + 净值日期”“操作”。每只基金只占一行；基金类型弱化在名称下方。操作保留“查看详情”和更多/编辑入口。状态通过紧凑标签表达正式净值、正式 + 估算、数据待补充、缓存数据和仅披露持仓。

用户金额快照、累计盈亏快照、正式净值参考市值、盘中估算参考市值、份额来源、数据来源、缓存说明和解释性文字全部下沉至详情抽屉；主列表不重复这些审计信息。窄屏允许水平滚动，但不得把桌面行退化为超高大卡。

### 添加与编辑抽屉

“添加基金”从右侧打开抽屉。先搜索代码或名称，结果显示名称、代码、类型、最新净值与日期；选中后显示识别结果。

默认快速模式只显示“当前持有金额（必填）”。“其他信息（选填）”默认折叠，包含当前累计盈亏、买入日期、备注和用户标签；“精确录入”作为该区域内的次级选项，继续保留持有份额和平均单位成本。标签支持多选与新增；系统识别标签不要求用户选择。

编辑复用同一抽屉，允许更新快照输入、精确字段、备注和标签。底部为取消及添加/保存按钮。

### 基金详情抽屉

保留基本资料、净值与走势、公开持仓披露、行业暴露、数据质量五个区域，以及 1月、3月、6月、1年、3年、全部六个范围。底部提供编辑持仓、删除持仓和关闭。删除始终使用页面内可访问的二次确认弹窗，不使用原生 `confirm`。

### 组合分析

基金列表之后显示组合重合度和组合行业集中度：

- 重合度默认展示最重要的 3 至 5 条证券、持有基金、组合估算暴露和重合数量，并提供“查看全部重合”。少于两只可比较基金时只显示紧凑提示。
- 行业集中度用进度条显示一级行业、保留未识别部分，并显示半导体、存储、机器人、消费电子等已有系统细分标签。无法计算时显示紧凑空状态。
