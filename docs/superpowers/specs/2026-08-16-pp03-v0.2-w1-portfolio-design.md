## 后端架构

新增 `backend/fund_data/`，按以下边界拆分：

- `models.py`：统一 `DataMeta`、Provider 返回值和能力名称。
- `cache.py`：用户目录 JSON 缓存、TTL、原子替换、过期数据显式降级。
- `providers/base.py`：Provider 能力声明与统一异常。
- `providers/eastmoney_direct.py`：基金搜索、净值 JS 标准化、批量股票行业/行情。
- `providers/akshare_provider.py`：东方财富基金档案、持仓、行业配置与蛋卷资料适配。
- `calculations.py`：历史收益、最大回撤、波动率、持仓盈亏、重复持仓和行业集中度。
- `service.py`：能力路由、主备切换、部分成功、缓存元数据、单基金和组合聚合。

API 页面只调用本地 FastAPI。第三方请求不进入 React。单一能力失败时，分析响应仍为 200，并在该模块返回 `unavailable` 或 `error` 元数据。

## 数据真值合同

每个外部模块返回 `data` 和 `meta`。`meta` 至少包含：

`source_name/source_reference/data_type/as_of_date/fetched_at/status/is_cached/is_stale/provider/fallback_used/message`。

`status` 使用 `official/disclosed/estimated/user_entered/stale/unavailable/error`。缓存不会隐藏原始真值；过期缓存改为 `stale` 并保留原状态。盘中估算始终带“这是估算，不是官方净值”、估算时间、持仓报告期、持仓覆盖率、行情覆盖率、公式和可信度。

## 持仓与迁移

V2 用户真值只保存 `code/shares/avg_cost/buy_date/notes/custom_tag_ids/created_at/updated_at`，并允许手动降级记录保存 `manual_name` 与未核验标记。派生基金资料、净值、持仓、行业、盈亏和系统标签不写入用户持仓真值。

首次读取 V0.1 文件时，在同目录生成保留原始字节的时间戳备份，再写入 `schema_version: 2`。旧 `tag_ids` 转为 `custom_tag_ids`；旧 `amount` 与 `cost` 保存为 `legacy_amount/legacy_cost`。因为旧 `cost` 语义不确定，`avg_cost` 留空并设置 `cost_confirmation_required: true`，页面要求用户确认后才计算收益。

## 计算与组合

- 总成本 = 份额 × 平均单位成本。
- 官方净值对应市值 = 份额 × 最新官方净值。
- 累计盈亏 = 市值 − 总成本；总成本为零时不计算收益率。
- 历史收益使用不晚于目标日的最近可用净值；最大回撤和年化波动率由净值序列本地计算。
- 重复持仓逐只股票列出基金、各基金披露权重和按基金市值加权的组合暴露。
- 行业暴露按基金市值权重与公开持仓权重相乘，保留未披露、未识别和非股票资产，不强制归一化。
- 盘中估算只在 A 股适用类型、持仓覆盖率至少 50%、行情覆盖率至少 90% 且披露不过期时计算；否则返回计划书规定的不可用说明。

## 前端结构与视觉

页面沿用暖橙玻璃主题与现有字体，不增加依赖。颜色继续使用现有 `primary/success/danger/warning/muted` 语义；正式、披露、估算、用户输入、缓存、过期、失败使用文字徽标而不只靠颜色区分。

桌面布局采用“组合账本 + 证据抽屉”：顶部是紧凑组合摘要；搜索添加区只展示代码/名称搜索和已选基金后的用户真值字段；当前持仓为高密度表格；组合重复度与行业集中度为横向证据区；基金详情用右侧抽屉承载五个规定区域。净值图使用可访问的 SVG，不连接超过 7 天的数据缺口，并提供 1月/3月/6月/1年/3年/全部范围。

完整标签库继续复用 `features/tags`。用户标签可增删；系统识别标签只读展示。删除持仓使用二次确认。图表、单基金、单模块失败均不使整页崩溃。
