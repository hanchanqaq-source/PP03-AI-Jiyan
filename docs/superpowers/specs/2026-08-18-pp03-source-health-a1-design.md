# PP03｜数据源扩展实验室 A1 已确认设计

**Work：** 数据源扩展实验室 A1：现有数据源体检与低风险修复
**范围：** 仅审计和报告当前基金、行情、行业与资讯数据链；不新增正式 Provider，不改变 Provider 优先级、主源或备用源顺序，不进入 A2、A3 或 V0.2-W3。

## 统一健康注册中心

新增独立的 `source_health` 层，统一登记实际 Provider 类与 RSS／Atom 来源，按“来源 × 能力”探测、评分、失败归类、修复价值判断及本地历史记录。注册中心只观察和报告既有数据链：不复制业务数据、不在运行时修改源码或数据源配置、不保存用户数据或凭据。

Provider 描述符从实际 Provider 和其 `capabilities` 自动生成；既有 `priority` 只读取而不复制为另一套优先级。资讯身份由 `hint`、`name`、`url` 三字段共同生成，因此同一 URL 在不同赛道仍是不同配置身份。

## 来源 × 能力评级

每个来源能力独立记录可用性、响应时间、字段完整率、数据新鲜度、连续失败和备用来源可用性。探测结果为 `success`、`partial` 或 `failure`；健康评级为 `healthy`、`usable`、`degraded` 或 `failed`。不适用的新鲜度或缓存维度从评分中移除，并对剩余权重重新归一化，不把不适用项计为零分。

错误分类包括超时、DNS、TLS、连接、HTTP、重定向、限流、认证、解析、空载荷、结构变化、过期和未知。错误原因必须脱敏：最多 200 字符，移除 Authorization、Cookie、查询参数中的 token/key、Windows 用户目录、完整本地路径和 traceback。

## 基金公开测试样本

健康体检固定使用一次公开目录发现得到的基金样本，不读取用户持仓、金额、成本、买入日期、备注或自定义标签。样本覆盖主动混合型、股票型、指数型、ETF 联接、债券型、货币型、QDII、FOF、新成立基金及公开披露不完整基金；每项保存实际验证后的代码、公开名称、实际类型、验证时间与公开目录来源。

样本按基金类型从公开目录匹配，代码升序选择首个可成功取得 profile 的样本；不因基金名称推断行业。找不到可靠样本时明确记录 `sample_status = unavailable` 与实际原因，绝不伪造代码。

## 资讯逐源探测

资讯探测复用生产抓取的请求、解码及 RSS／Atom 解析路径，不写正式 `radar.json`、不读取用户数据、不合并事件。它支持 RSS 2.0、Atom、命名空间 Atom、gzip 和非 UTF-8 编码，并记录公开最终地址、HTTP 状态、是否重定向、内容类型、返回条数和最近发布时间。

对 timeout、connection、TLS 临时错误及 HTTP 408、429、500、502、503、504 最多重试一次；遵守 Retry-After，最多等待五秒，无 Retry-After 等待 0.5 秒。401、403、404、410 与解析错误不重试；绝不关闭 TLS 校验。

## 初始评级与稳定评级分离

评级置信度为 `initial`、`growing` 或 `stable`。少于三个不同日期或少于五个样本时是初始评级；达到至少三个不同日期及五个样本、但未达到七个不同日期及二十个样本时是增长中；达到至少七个不同日期及二十个样本才是稳定评级。首次全量体检必须标识为初始评级，而不得冒充长期稳定结论。

## 90天 JSONL 历史

健康观察以 JSONL 本地持久化，支持原子写和并发追加，保留最近 90 天记录。`current-summary.json`、`last-run.json` 与历史记录服务于健康诊断；缓存管理只能回收本任务的过期健康历史，不得删除用户数据、持仓文件、正式配置或验收文档。

## 启动快速检查

后端启动后在后台执行快速检查，最多每 24 小时一次，仅包含 `critical=True` 的关键来源与能力。它不等待网络、不阻塞 API 启动，失败也不阻塞服务；`VR_SOURCE_HEALTH_STARTUP=0` 可在测试和隔离验收中禁用。

## 手动全量体检

用户可以手动发起全量体检，覆盖全部基金能力和全部资讯配置。基金／行情／行业探测最大四个工作线程，资讯最大二十个；单一 Provider 的非线程安全能力串行。全量体检同一时间只允许一个运行，已有运行时返回 HTTP 409 和“数据源体检正在运行”。完成状态写入最近结果和 90 天历史，部分来源失败不得使整次体检失败。

## 数据说明中的健康入口

在既有“市场资讯 → 数据说明”中显示数据源健康摘要，并提供“查看详情”和“运行全量体检”。详情按“基金与行情 Provider”和“资讯来源”分组，逐行显示来源名称、能力、状态、响应时间、返回条数、数据日期、字段完整率、最近成功、连续失败和修复价值；失败详情只展示脱敏原因、最终公开地址、重定向、备用来源与建议处理。

界面不得新增一级导航、不得展示请求头、Cookie、Token、完整异常堆栈或本地隐私路径。运行期间显示进度、每两秒轮询且禁止重复启动；失败时保留上一次成功报告。支持 Escape 关闭详情抽屉并把焦点还给“查看详情”，状态不能只依赖颜色。

## 允许的低风险修复

允许修复必须有 before／after 审计和对应测试，并且不改变业务数据含义：同一官方公开来源明确 301/308 的 URL 更新；仅补充公开请求需要的 User-Agent、Accept、Accept-Encoding 或来源公开页面 Referer；实际格式所需的 RSS／Atom／XML、gzip、字符编码和明确字段解析兼容；来源身份冲突、完全重复配置、错误原因脱敏及缓存／实时状态误标修复。

仅当 `hint`、`name`、`url`、`language`、`region` 完全一致时可去重；同一 URL 跨赛道绝不删除。每项修复记录 source_id、修复前状态、根因、修改文件和内容、低风险理由、测试、修复后状态，以及“是否改变业务数据含义：否”。

## 禁止的高风险变更

禁止新增 efinance、yfinance、FRED、EIA、SEC、RSSHub 等正式 Provider；禁止申请、读取或写入 API Key，使用登录 Cookie，绕过反爬、登录、权限或付费墙，抓取禁止自动访问页面，关闭 TLS 校验，使用外部共享 Key，运行时改写源码或数据源配置，或调整 Provider 优先级与主备顺序。

禁止根据基金或股票名称推断行业，禁止把官方行业配置当作重仓股穿透结果，把产业链标签当作行业配置比例，或归一化未知、未披露股票及非股票资产。401/403、登录墙、验证码、Cloudflare 挑战、付费 Feed、robots 或条款限制、需要关闭 TLS 的来源及需要改变优先级的情形只可记录为 `observe`、`replace_candidate` 或 `disable_candidate`，不得自动修复。

完成 A1 后必须停止，不自动进入 A2 新增金融数据源、A3 AI API／免费额度网关或 V0.2-W3 行业研究。
