# PP03 V0.2-W2 查询范围一致性修复设计

## 状态

本设计由用户在 2026-08-17 明确提出并批准，仅修复 V0.2-W2 市场资讯的筛选、状态和证据范围串线。不得进入 V0.2-W3、行业研究、投研首页、AI 选基或 Windows 打包。

## 已确认根因

1. `MarketNewsService.get_events` 只在 `my_focus` 分支应用 `tag_ids`；`my_holdings`、`global_tech`、`domestic_policy` 只应用模式条件。
2. `today_focus` 与 `impact_summary` 从 `all_events` 计算，因此不跟随 mode、tag_ids、category、days 和 sort。
3. `MarketNews.tsx` 使用单个全局 `dataRef` 保存最后成功响应；新 query 失败时会把旧 query 的事件和侧栏继续显示在新的筛选标题下。
4. 详情快照 ID 只包含基础数据和标签，没有包含完整查询，也在过滤前保存所有事件。

## 方案选择

采用“服务端唯一查询边界 + 前端按 query key 缓存完整响应”的方案。

- 不采用前端再次本地过滤：前端没有足够的来源 provenance 和持仓证据，且会造成前后端口径分裂。
- 不采用单纯清空全局缓存：这只能避免失败串线，无法修复后端三种模式和侧栏统计的范围错误。
- 不重构为新的通用搜索平台：本次只修复 W2，保持改动集中在现有 Market News 服务和页面。

## 后端数据流

每个请求严格按以下顺序处理同一事件集合：

1. 按 `days` 过滤发布时间。
2. 按 `category` 过滤分类。
3. 按 `mode` 过滤模式：
   - `my_focus`：要求至少一个当前标签；模式本身不引入额外事件。
   - `my_holdings`：只保留 `direct_holding` 或 `industry_relation`。
   - `global_tech`：只保留全球科技来源。
   - `domestic_policy`：只保留 `category=policy` 且至少一个来源 `region=CN`。
4. 所有模式统一按当前 `tag_ids` 过滤。匹配集合只取 `event.tag_evidence` 中 `provenance=article_text` 的标签；`feed_track` 不得通过当前行业标签过滤。
5. 按请求的 `sort` 排序。

过滤完成后的集合是本响应的唯一事实范围：

- `events` 返回完整过滤结果。
- `focus_events` 返回该结果按当前排序的前五项，前端名称为“当前筛选重点”。
- `impact_summary` 只统计该结果，前端按 `filters.days` 显示“今天”或“过去 N 天”。
- `snapshot_id` 由基础事实版本和完整标准查询生成，详情快照只保存本次过滤结果。
- `filters` 返回服务端实际执行的完整标准查询。

保留 `today_focus` 作为兼容别名没有价值且容易继续误导，因此 API 与前端类型统一改为 `focus_events`。

## 前端状态模型

标准 query key 为：

```text
mode|sorted(tag_ids)|category|days|sort
```

页面使用 `Map<queryKey, MarketNewsResponse>` 保存每个查询最后一次成功响应，并遵守：

1. query 切换时立即只读取该 query key 的缓存；没有缓存则清空事件、侧栏和详情。
2. 响应写入前比较 `response.filters` 与发起请求时的标准 query；不一致按当前 query 失败处理。
3. 当前 query 失败且已有同 key 缓存时，保留该缓存并显示“当前筛选加载失败，继续显示该筛选上次成功结果。”
4. 当前 query 失败且无同 key 缓存时，不显示其他 query 数据，展示“当前筛选加载失败”空状态。
5. request ID 继续阻止旧响应覆盖新 query；query 切换同时关闭旧详情抽屉。
6. 事件流、侧栏、影响统计、filters 和 snapshot_id 始终来自同一个 `MarketNewsResponse` 对象。

## 文案与口径

- “今日重点”改为“当前筛选重点”。
- “我的持仓影响”改为“当前筛选影响”。
- `days=1` 显示“今天有 X 个事件与你的持仓相关”。
- `days=3/7/30` 显示“过去 N 天有 X 个事件与你的持仓相关”。
- 无同 query 缓存的失败空态不得展示事件、重点或影响数字。

## 测试与验收

后端回归覆盖四种模式的正文标签过滤、feed-track 排除、范围化重点与影响统计、完整快照查询；前端回归覆盖跨 query 失败隔离、同 query 失败回用、旧响应隔离、filters 不一致拒绝和整页同快照更新。

Computer Use 使用同一批隔离公开数据依次验收：国内政策+半导体、国内政策+存储、我的持仓+半导体、我的持仓+机器人、全球科技+存储，以及切换标签时的当前 query 请求失败。截图写入 `docs/screenshots/v0.2-w2/`，临时数据仅位于 `.tmp/acceptance/v0.2-w2` 并在验收后删除。
