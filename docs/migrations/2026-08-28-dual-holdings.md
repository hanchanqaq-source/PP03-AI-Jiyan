## 存储边界

- 基金持仓：`%VR_DATA_DIR%/fund-portfolio.json`，当前写入 schema v3。
- 股票持仓：`%VR_DATA_DIR%/portfolio.json`，继续使用原生股票数量/成本模型。
- 两个文件、运行模型和写入路径完全隔离。基金代码不得写入股票文件，股票记录不得转换成基金金额模型。

## 只读兼容

基金 v1/v2 文件在读取时先完整校验，再只在内存中规范化为当前运行模型。列表、详情、组合分析、页面刷新以及基金/股票页签切换均不调用持久化函数。只读前后原文件 SHA-256、字节数和 mtime 必须完全相同；内存转换结果明确标记为未持久化。

schema v3 继续按现有格式使用，但普通读取同样不回写时间戳、排序或默认字段，不产生无意义写盘。

## 首次主动写入

只有用户主动添加、编辑或删除基金时，旧 schema 才允许迁移：

1. 在锁内重新读取并完整验证原始文件及每条记录，拒绝损坏结构、非法类型、重复代码和交叉字段矛盾。
2. 将旧数据规范化为 v3，并在任何备份或写入之前再次按 v3 合同验证。
3. 在同一用户数据目录创建唯一、带 schema 与时间戳的备份文件；创建方式不得覆盖既有备份。
4. 重新读取备份并校验字节数和 SHA-256 与原文件一致。
5. 写入同目录唯一临时文件，flush 后以原子替换落位 v3。
6. 成功响应才可声明迁移已持久化；备份保留，不自动删除。

## 失败关闭

- 旧文件校验失败：停止操作，不创建备份或临时文件。
- 备份创建、读取或哈希校验失败：原文件不变，清理失败备份，停止操作。
- 规范化 v3 校验失败：在备份和写入之前停止，原文件不变。
- 临时写入或原子替换失败：原文件保持完整，清理临时文件，页面显示明确错误。
- 任一步骤失败都不得留下半迁移状态，不得把内存转换误报为持久化成功。
