# V0.2-W2 数据来源、判定依据与限制

## 资讯来源

- 继续复用 `backend/news_sources.json` 的 108 个公开 RSS/Atom 源。
- 每条原始资讯保留来源名称、源 URL、原始 URL、发布时间、抓取时间、标题、必要摘录、语言、区域与数据状态。
- 同一事件按标准化标题、实体、关键词、48 小时时间窗与来源域名做保守聚合；不确定时保留为不同事件。缺失或无法解析的发布时间保留为未知，不使用抓取时间补造，也不进入“今天/近 N 天”或“今日重点”。
- 详情只显示必要摘录和原始链接，不复制新闻全文。

## 基金与持仓来源

- 基金档案、公开前十大持仓和官方行业配置：AKShare / 东方财富基金档案。
- 正式净值：东方财富-天天基金；净值仅用于 W1 持仓能力，本页面不把它解释为实时价格。
- A 股上市公司行业分类：巨潮资讯上市公司行业归属。
- 关系链只使用公开披露字段：基金代码/名称、披露日期、股票代码/名称、行业分类及其来源。

## 三层关系判定

1. 直接持仓：事件标题或来源摘要命中最新公开重仓公司的名称、完整股票代码；含字母的海外披露代码可去除前导零后按完整单词匹配（例如 `00NVDA` → `NVDA`），避免子串误命中。
2. 产业关联：事件正文提取的具体行业/产业标签命中重仓公司的有来源行业分类；RSS 赛道归属只用于发现和低置信度关注筛选，不能建立产业关系。
3. 关注标签：没有持仓证据时，事件命中市场资讯页当前主动选择的标签。

优先级固定为：直接持仓 > 产业关联 > 关注标签 > 普通资讯。基金名称、营销主题、页面标签本身都不能生成“直接持仓”。

## 排序依据

- 重要度：直接持仓、政策/公司正式事件、产业关联、关注标签、普通资讯依次降级，再按时间与稳定事件 ID 排序。
- 最新时间：按事件最新发布时间，再按稳定事件 ID 排序。
- 持仓相关性：直接持仓、产业关联、关注标签优先，再使用确定性规则打破并列。
- AI 不参与首版确定性排序。

## AI 边界

- 未配置模型时，页面使用原始标题与来源摘要，显示“AI摘要暂不可用”。
- 非中文资讯永久保留原始标题、原始摘要与原始链接；中文翻译写入独立字段，默认优先显示中文，并可切换原文。
- 翻译只提交当前页最多 20 条的标题、现有摘要与原文语言，内容哈希缓存包含三者；相同内容不重复调用模型。
- 翻译复用项目既有可配置模型入口，不增加第三方翻译服务；未配置模型、模型失败或返回不合规时保留原文并标记“中文翻译暂不可用”。
- 影响倾向默认“影响不明确”，不会仅凭标题给出确定金融结论。
- 不生成新闻、政策、持仓、公司关系或金融数字，不输出买卖、加减仓指令。

## 缓存与失败

- 成功刷新原子替换缓存，避免并发写坏文件。
- 单个来源失败时保留其他来源结果，并可回用该来源的最后缓存。
- 全部来源失败且存在缓存时返回过期缓存；无缓存时返回明确来源失败/空状态。
- 刷新接口失败时，前端保留最后一次成功事件，不把页面清空。
- 缓存、过期缓存与部分刷新会把状态落实到每条来源和事件卡；缓存内容不会继续显示为“实时抓取”。
- 同目录唯一临时文件、进程内写锁、`fsync` 与原子替换共同避免并发刷新写坏缓存。
- 事件基础快照按资讯内容和持仓稳定事实版本复用；详情用查询快照 ID 隔离不同标签/筛选请求。
- 巨潮令牌运行时的进程级初始化被串行化，并按调用线程缓存 isolate，避免并发请求初始化 V8 时直接终止后端进程。
- 来源失败明细使用稳定的配置来源 ID，不接受页面传入任意 URL；错误只归类为 timeout、HTTP 状态、TLS、DNS、连接、XML/RSS 解析或未知，并在 200 字符内脱敏。
- 旧 `radar.json` 的来源状态会在内存中补齐新诊断字段而不改写缓存文件；旧缓存没有具体异常证据时明确显示“旧缓存未记录具体失败原因”，不猜测异常。
- 单源重试失败不改写 `radar.json`；成功时仅合并该配置来源，并用一次完整响应同步事件、当前筛选重点、当前筛选影响、筛选参数和快照。

## 缓存清理边界

- `radar.json` 继续使用单文件原子替换，不产生无限历史文件。
- 股票盘中行情在过期后保留 1 天；基金搜索、资料、正式净值和历史净值保留 30 天；基金公开持仓、官方行业配置和股票行业分类保留 180 天；中文翻译按最后访问时间保留 90 天。
- `.tmp/acceptance` 成功验收立即清理，异常遗留超过 7 天可回收；应用日志保留 14 天并设 50 MB 类别上限。
- 应用缓存默认上限 500 MB，超限时依次回收最旧临时文件、过期翻译、过期行情、30 天基金缓存、180 天基金缓存和日志。
- 当前持有基金最新一份有效缓存可固定为 pinned。清理器只处理注册根目录，不删除真实持仓、标签设置、有效缓存、源代码、依赖锁文件或 Git 跟踪截图。
- 后端启动时最多每 24 小时自动清理一次；状态接口返回总量、分类大小、文件数、过期数、上次自动清理时间、可回收量和上限。页面手动按钮只清理过期与临时缓存。

## 当前限制

1. 当前仅对 8 个可审计的中国大陆公开来源显式配置 `language=zh-CN`、`region=CN`；国内政策模式严格依赖该字段，因此结果仍可能偏少，系统不会根据中文标题擅自补区域。
2. 海外 QDII 重仓股的巨潮 A 股行业分类通常不可用；可核验公司名称/完整代码仍能形成直接关系，但不会伪造产业穿透。
3. 聚合为保守规则：相近但证据不足的报道会保留多条；宁可少合并，不错误合并不同事件。
4. 分类是确定性规则而非全文语义模型；已收紧“基金公告”规则，单独出现“市场份额”或普通“定期报告”不会被视为基金公告。
5. 今日重点基于当前公开源和确定性重要度；来源没有持仓或标签证据时会明确显示“普通资讯”。
6. 108 表示来源配置条目，不等于 108 个唯一 URL；少数同源跨赛道映射仍会重复抓取，但事件层会按原始 URL 去重。
7. 中文翻译质量取决于用户配置的现有模型；隔离浏览器验收没有读取用户模型凭据，因此实测的是“不配置模型时保留原文”降级路径，有翻译时的中文默认与原文切换由自动化回归测试覆盖。
8. 旧缓存无法还原当时已被吞掉的原始异常；兼容层只能诚实标记“旧缓存未记录具体失败原因”。下一次单源重试或刷新后才会得到新的、分类且脱敏的错误证据。
9. 生产构建仍提示主入口压缩后约 695 kB，属于既有前端分包优化项，不阻塞 W2 功能；本轮不进入 W3 或做架构拆包。
