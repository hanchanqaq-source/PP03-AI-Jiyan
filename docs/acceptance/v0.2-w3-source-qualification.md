## Request boundary and prohibited surfaces

The safe client issued only a GET for the public current-price URL, with a fixed public
User-Agent and an HTML Accept header. It performs no automatic retry and the live test
set `max_redirects=0`, so no redirect target could be requested.

The following surfaces were not requested:

- TrendForce historical price or history download;
- TrendForce member, login, download, subscription, or enterprise pages;
- WSTS or SIA subscription data;
- any API-key, Cookie, credential, paid, freemium, or account-only path.

Offline redirect tests additionally prove that login, member/download, history,
subscription, and WSTS targets are rejected before a second request is sent.

## Enablement boundary

Future enablement requires every condition below at the same time:

- complete source identity, request/final URL, HTTP status, response cap/bytes;
- exact target fields and stable observed field shape;
- verified data date, USD unit, and current-snapshot frequency;
- complete declared failure-mode policy and no active failure;
- explicit `verified_public_current_snapshot` license conclusion;
- `BillingModel.FREE_NO_KEY`, `auth_type=none`, and empty credential names;
- catalog status `CONFIGURED` and `default_enabled=True`;
- no login, Cookie, member, download, history, subscription, or redirect dependency.

The 2026-08-25 qualification does not meet these conditions. Production Live refresh
therefore remains unavailable.
